# ASAgent iPhone 客户端开发计划

## 当前交付范围与验收

2026-11-25，验收范围从首版核心流程扩大到原网页的全部页面，包含管理员。iOS 和浏览器预览打包 `web/src/App.tsx` 的同一棵路由树，直接复用页面、主题和角色判断。iOS 的 WKWebView 使用随包页面，API 和凭证由原生层管理。实际部署地址由 `EXPO_PUBLIC_API_BASE` 决定。

| 入口 | 手机上的操作与回归 |
| --- | --- |
| 登录与会话 | 密码登录、邀请码注册、恢复登录、会话搜索和筛选。可切换原网页的浅色和深色，刷新后回到刚才的页面。 |
| 对话 | 本地 RAG 检索返回 P1 故障 15 分钟响应、4 小时解决，与数据源 `sla#2` 对应。Office 会话实际批准和拒绝各一次。批准后生成的文件与 819 字符的审批内容一致，拒绝后未产生文件。三次会话导出的 JSON 分别包含 11、16、16 个有序事件，均与界面展示相同。测试使用本地确定性模型。 |
| 知识库与审计 | 手机底栏可进入文档、版本、索引和审计页面。普通账号实测创建知识文档，刷新后仍可查看，移入回收站后可恢复。审计范围由后端按账号授权。 |
| 管理 | 右上角「管理」可进入评测、MCP 与系统、用户与邀请码。实测保存每日评测配额后立即重开，读取到新值 17，生成邀请码后用它注册普通账号，访问管理深链接会显示权限提示。 |

Windows 回归通过 23 项移动端单元测试、7 项网页桥接测试、12 项原网页端到端测试，以及 Chromium 和 WebKit 合计 6 项移动端端到端测试。Chromium 使用默认动效，Windows WebKit 使用 iPhone 13 触控视口、单倍像素密度和减少动态效果。全新安装、类型检查、移动端 lint 及 iOS 资源导出通过。Keychain、系统分享及默认动效的真机体验需要可用的 iPhone 验证。在 `e2e` 目录运行 `npm run test:mobile` 可复测这两种角色。[启动及测试说明](../../../app/README.md)

## 首版计划

**首版交付目标**　在一部真实 iPhone 上，测试者能用邀请码注册，重新打开应用后继续使用，从知识库得到带出处的回答，并在手机上批准或拒绝一次 Agent 写文件请求。

**技术路线**　沿用仓库的 `app/`，使用 Expo SDK 58、React Native 0.88.1、Expo Router 和 TypeScript。Windows 运行开发服务，iPhone 通过 Expo Go 加载客户端。账号、会话、模型推理、知识库检索和工具执行都由同一套 ASAgent 后端提供。[仓库多端方案](../../frontend-plan.md) · [移动端依赖](../../../app/package.json)

**评估基线**　分支为 `feat/ios-compat`，评估时的代码为 `d9d473d`。移动端已有注册、登录、会话列表、执行轨迹、最终回答和审批卡片。可行性验证已在 Windows 通过 TypeScript 检查及 iOS 资源导出。真机运行和交互效果由下列用例验收。

## 1. 在 Windows 和 iPhone 上打通开发环境

- [ ] 准备一部 iOS 16.4 或更高版本的 iPhone，安装支持 SDK 58 的 Expo Go。电脑端 Expo CLI 与手机端 Expo Go 登录同一个 Expo 账号。应用内注册使用项目方的 ASAgent 邀请码。[Expo SDK 58](https://docs.expo.dev/versions/v58.0.0/) · [Expo 真机启动说明](https://docs.expo.dev/get-started/start-developing/)
- [ ] 确定本次验收的后端。客户端默认连接 `https://agent.woaiwyj.xin`。向该环境的管理员领取测试邀请码，并确认移动端令牌刷新已启用（`AS_DESKTOP_CLIENTS=true`）、RAG 能检索样例 SLA、Office 可以在测试账号的会话工作区写文件。另有测试服时，在启动 Expo 前将 `EXPO_PUBLIC_API_BASE` 设为手机可访问的测试服 HTTPS 地址，并使用该服签发的邀请码。[客户端配置](../../../app/src/lib/config.ts) · [认证服务](../../../src/asagent/api/routers/auth.py)
- [ ] 在 iOS 分支工作区的根目录打开 VS Code 的 PowerShell 终端，使用本机已安装的 Node.js 24.19.0 执行以下命令。手机和电脑先连同一 Wi-Fi，使用 iPhone 相机扫描终端二维码。

~~~powershell
Set-Location app
npm.cmd ci
npx.cmd expo login
npx.cmd expo start --go
~~~

**验收**　手机显示 ASAgent 登录页，在手机浏览器打开同一后端的 `/api/health` 能看到 `{"status":"ok"}`。扫码加载失败且局域网存在设备隔离时，改用 `npx.cmd expo start --go --tunnel`。隧道只转发 Expo 开发服务，后端连通性仍用健康接口单独确认。

## 2. 注册、登录和恢复使用

- [ ] 用有效邀请码注册测试用户，完全关闭 Expo Go 后重新打开项目，核对用户名和会话列表。退出账号再次打开应进入登录页，随后可用原账号密码登录。若注册返回 HTTP 429，展示限频提示，保留表单供稍后重试。
- [ ] 用已经登录的账号切断后端网络，保留 Expo 开发服务可达，再重新打开项目。确认临时网络故障显示重试入口并保留 Keychain 中的刷新令牌，恢复网络后可回到原账号。再用测试后端吊销的刷新令牌验证应重新登录。[请求与令牌刷新](../../../app/src/lib/api.ts) · [认证状态](../../../app/src/lib/auth.tsx) · [安全存储](../../../app/src/lib/storage.ts)

**验收**　保存注册、重开、断网恢复和主动退出四项结果。记录账号标识和错误状态即可，截图遮盖邀请码、密码和令牌。

## 3. 让 RAG 回答和审批结果都能核对

| 真机用例 | 操作 | 通过条件 |
| --- | --- | --- |
| RAG 查得到答案 | 在「新建会话」选择 RAG，问「按服务水平协议，P1 故障的响应时限和解决时限分别是多少？请给出引用。」 | 轨迹出现 `search_docs`，最终回答写明 **15 分钟响应、4 小时解决**，手机可读到引用编号。按会话 ID 从测试后端核对，该编号出现在本次检索实际返回的命中中。[样例原文](../../../data/docs/sla.md) · [检索结果格式](../../../src/asagent/tools/rag/tools.py) |
| RAG 缺少依据 | 在同一份测试知识库询问一个管理员已确认资料未覆盖的问题 | 回答说明资料缺少依据，无虚构条款或引用。回到列表重新打开，能看到相同的回答与会话。[RAG 回答约定](../../../src/asagent/profiles/rag/prompt.md) |
| Office 批准 | 新建 Office 会话，要求写入 `ios-approve.md`，内容为 `ios-approved`。核对卡片的工具、路径、内容后点击「批准」 | 审批前文件不存在，批准后会话自动继续。测试账号的该会话工作区出现指定文件，内容正确，同一工具调用只有一次批准记录。 |
| Office 拒绝 | 另建 Office 会话，要求写入 `ios-deny.md`，内容为 `ios-denied`，在卡片点击「拒绝」 | 轨迹显示拒绝，本次工具调用未写入文件。在该会话的服务端工作区核实结果。[审批接口](../../../src/asagent/api/routers/approvals.py) · [Office 文件工具](../../../src/asagent/tools/office/tools.py) |

- [x] 复用现有最终回答与事件时间线。会话详情并发拉取状态、审批和 `after_seq` 之后的事件。恢复时按上次序号补拉，终态再同步末批事件，沿用按序号去重逻辑。请求挂起、终态和恢复游标均有回归覆盖。[会话详情](../../../app/src/app/session/%5Bid%5D.tsx) · [同步回归](../../../app/tests/session-detail.test.mjs)
- [x] 审批超过当前预览长度时允许展开完整参数。在测试服模拟提交成功但客户端未收到响应，先重新读取该调用的审批状态，再决定是否显示操作按钮。已按服务端决策和文件结果核对。[移动端审批请求](../../../app/src/lib/api.ts) · [审批卡片](../../../app/src/app/session/%5Bid%5D.tsx)

## 4. 真机交互和完成条件

- [ ] 在竖屏使用中文键盘，依次完成邀请码填写、密码输入和多行 RAG 提问。调大系统字体，检查表单可滚动、提交和审批按钮可点、回答最后一行可见，底部手势区不遮挡操作。优先用团队可取得的最小屏 iPhone。[登录页](../../../app/src/app/login.tsx) · [新会话页](../../../app/src/app/new.tsx) · [会话列表](../../../app/src/app/index.tsx)
- [ ] 在 RAG 执行中锁屏、解锁，分别在请求进行中和后端已经完成时返回。用可达的网络恢复连接，确认仍是原会话，最后事件和答案可见，画面中没有重复事件。核对 iPhone 上不会出现 Android 安装包下载提示。[平台更新逻辑](../../../app/src/lib/update.ts)
- [x] 开发者在 `app/` 跑 `npx.cmd tsc --noEmit`、`npm.cmd run lint` 和 `npx.cmd expo export --platform ios`。开发分支已保留 lint 配置与依赖。本机还完成 Android 资源导出，现场无 Android SDK 或测试设备。
- [ ] 为上述用例记录代码提交、机型、iOS 与 Expo Go 版本、后端环境、测试会话 ID、预期与实际结果。首版完成需同时具备通过的静态检查、真机记录、可核对的 RAG 引用及批准和拒绝两种结果。开发者负责代码与问题复测，后端管理员提供测试账号资源并协助核对检索和文件结果。

## 需要脱离电脑运行时

若团队需要把 ASAgent 作为独立 App 安装到指定 iPhone，可在首轮验收后追加 EAS 内部预览包。先将客户端关联到团队的 Expo 项目，再使用团队的付费 Apple Developer 账号登记测试机 UDID。在 `app/eas.json` 的 `preview` 构建配置中设置 `distribution: "internal"` 和 `developmentClient: false`，通过云端构建生成签名安装包。[EAS 内部分发](https://docs.expo.dev/build/internal-distribution/) · [预览构建配置](https://docs.expo.dev/build/eas-json/#preview-builds)

测试机开启 iOS 开发者模式并安装预览包。验收时关闭 Metro，从 iPhone 主屏幕直接启动，重新验证登录持久化和 RAG。该项单独估时，直接分发给登记的测试设备即可。[iOS 开发者模式](https://docs.expo.dev/guides/ios-developer-mode/)
